## Other observations (no finding, or cross-scope)

- **Nullptr checks.** `ms_device_battery.rs:204` and `:224` guard `sf` the same way C++ does (`sf != nullptr || ...`, `if (sf != nullptr)`). `ms_device.rs:172-178` only casts `into.last()` after confirming a push. `ms_vehicle.rs:3130` and `:7778` guard their pointers. No unconditional C++-legal null dereference found in scope. Unverified: `ms_vehicle.rs:7767` derefs `myDriverState` without a guard, but C++ `getDriverState` is equally unguarded and callers check `hasDriverState` (ms_vehicle.rs:7802).
- **Constants.** `DEFAULT_MAX_CAPACITY = 35000` and `DEFAULT_CHARGE_RATIO = 0.5` (ms_device_battery.rs:79, 81) match MSDevice_Battery.cpp:40-41. The `150000.`, `0.1` defaults at `ms_device_battery.rs:211-212` match C++ lines 66-67.

- **Stale comment.** `ms_device_fcd.rs:19-21` says MSGlobals is unported, but line 585 calls `MSGlobals::use_meso_sim()`. Cosmetic.
- **`MSDevice::save_state` through base.** `mesosim/me_vehicle.rs:1504` calls `dev.m().base2.save_state(out)`, which writes "cannot save state" instead of the device's state (C++ virtual dispatch). Mesoscopic only, not verified as reachable.
- **Cross-scope (owned, not analysed).** `ms_device_routing.rs` has no vt (no `vt` hits in that file), so the same row 2 and row 3 issues likely apply to its `notify_enter` (DEPARTED reroute) and `notify_stop_ended`. Owner should check.
