# AUDIT au09: microsim/output/ and microsim/trigger/

Scope: `crates/sumo_core/src/microsim/output/`, `crates/sumo_core/src/microsim/trigger/` (ms_triggered_rerouter.rs excluded, owned elsewhere).
Method: static read of Rust and C++ (`C:\Users\karti\sumo-src\src`). No cargo run, no tests run. Every row is **verified by reading** unless marked **unverified**. Runtime impact is inferred from dispatch paths, not observed.

Root cause shared by rows 1 to 6: `MSMoveReminder` dispatches `notify_enter/move/leave` through `self.vt` (`ms_move_reminder.rs:110-128, 169`). The default table (`ms_move_reminder.rs:384-398`) returns `true` and does nothing. No output/ or trigger/ type ever assigns its own `vt`. `grep '\.vt\s*=|base2?\.vt'` over `output/` and `trigger/` returns zero hits. The rerouter is the only exception (`ms_triggered_rerouter.rs:183`, owned elsewhere). Lane and vehicle code call the reminder through `Ptr<MSMoveReminder>`, so the subclass overrides are never reached.

## Cross-cutting

Each reminder subtype needs its own `MSMoveReminderVt`. The shims cast `&mut MSMoveReminder` to the derived type with `Ptr::cast`. This requires `#[repr(C)]` with `base` first on each derived struct, which AGENTS.md says is the convention. Installation must happen after the struct has its final heap address, in the same place as the lane registration.
