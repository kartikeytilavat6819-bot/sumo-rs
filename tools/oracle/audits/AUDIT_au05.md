Rank order is by impact. "Certain" means the path is reached on any run that selects the model or option. "Possible" means it needs a specific option, model, or traffic situation.

## Checked and clean

- **Abstract vt coverage.** Every C++ virtual that LC2013, SL2015 or DK2008 overrides is in the base table, except DK2008 (row 1).
- **LC2013 table** (mslcm_lc2013.rs:137-162) covers all LC2013 header overrides: inform, patchSpeed, changed, resetState, getSafetyFactor, getOppositeSafetyFactor, prepareStep, getParameter, setParameter, computeSpeedLat, saveBlockerLength, saveState, loadState, debugVehicle, wantsChange.
- **SL2015 table** (mslcm_sl2015.rs:174-199) covers all 12 SL2015 header overrides, including updateSafeLatDist, getDesiredAlignment, resetState, saveBlockerLength, setOwnState, updateExpectedSublaneSpeeds, decideDirection.
- **LC2013_CC** overrides only `checkChangeBeforeCommitting` and `getModelID`. Rust inherits the LC2013 table correctly. Only row 4 is open.
- **Non-overridden base virtuals** (`estimateLCDuration`, `sublaneChangeCompleted`, `congested`, `predInteraction`, `getAssumedDecel...`, `resetSpeedLat`) have no subclass override in C++ either. Rust needs no table entry.
- **resetState and sublaneChangeCompleted** have no C++ callers. No Rust callers are needed.
- **MSLaneChanger virtuals.** Sublane overrides of `change`, `initChanger`, `updateChanger` are reached via `lane_change_sublane` (ms_lane_changer_sublane.rs:229-236, routed from ms_edge.rs:2573-2574). Correct.
- **Constants.** These match C++ exactly: LC2013 and SL2015 `#define`s, DK2008 LOOK_FORWARD_*, JAM_FACTOR2, OPPOSITE_OVERTAKING_* (ms_lane_changer.rs:16-24), SUMO_const_haltingSpeed 0.1, SUMO_const_laneWidth 3.2, VTYPEPARS_MAXSPEED_LAT_SET = 1<<20, LC_ASSUMED_DECEL 1.0 (ms_abstract_lane_change_model.rs:2783-2788, MAX2 order preserved).
- **DK2008 JAM_FACTOR=2** appears in C++ only inside a `/* */` block (MSLCM_DK2008.cpp:432-437). Not live.
