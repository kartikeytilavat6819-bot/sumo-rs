## Notes

1. **Not measured: SL2015 selection by name.** There is no global option for the lane-change model; it is a vType attribute, and the case's `routes.rou` is fixed. The `lanechange/lat04` row covers the path C++ forces when `--lateral-resolution > 0` (`MSAbstractLaneChangeModel.cpp`).
2. **Existing references regenerated in scratch only.** Committed `ref.*` files are untouched. Config paths in C++ tripinfo headers differ, so the scratch copies are not byte-identical to the committed ones; only the variant files were copied in.
3. **Interrupted C++ runs.** Several C++ runs during generation printed `Interrupt signal received` and wrote truncated output (0-trip tripinfo). Those were discarded and rerun until every log was clean. Source of the SIGINT was not identified; anyone regenerating references should check for that line in the logs.
4. **Regression rows from the same loop** (not variants, but measured with the same binary): `reroute/closing` PASS, `reroute/device` PASS (SCOREBOARD recorded FAIL for `devices` on c4dcf59; this binary differs, so it's not comparable), `reroute_contention/adapt` PASS, `sigma_seed/seed7` PASS.
5. `real/reroute` was not regenerated (its committed reference is untouched).

Reproduce: `DEST=<scratch> bash tools/oracle/make_sim_refs.sh real signal stress lanechange reroute_alt`, then run `sumo.exe` with `-n ref_simple.net.xml -r routes.rou $(cat sim_<v>.args)`.
