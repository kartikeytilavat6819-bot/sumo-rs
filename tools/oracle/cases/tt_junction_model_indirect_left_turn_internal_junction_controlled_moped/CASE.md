# Imported TextTest case

Source: `junction_model/indirect_left_turn/internal_junction_controlled_moped` (SUMO 1.28.0 official TextTest suite).

Collated options (`options.sumo`, parent first):

```
--write-license --default.speeddev 0 --default.departspeed 0 --default.departlane first -r input_routes.rou.xml -n net.net.xml --no-step-log true --collision.check-junctions true --duration-log.statistics -a input_additional.add.xml
```

`sim.args` keeps the behaviour options; net/route/additional/output files
are copied into this case and the net/route are exposed as
`ref_simple.net.xml` / `routes.rou`. TextTest-specific output files are not
imported; run_all compares tripinfo/fcd/statistics regenerated by the
official sumo via `make_sim_refs.sh`.

## Known divergence (not a C++ nondeterminism)

This case currently FAILS: the scooter `flow_2.4` enters internal lane `:C_10_0`
at t=61 with speed 8.40 in the official output but 9.29 in ours (pos 0.86 vs
1.75), then brakes harder and stops at the same position (pos 10.80). The first
knock-on effect is `flow_0.52` arriving at 424.00 (official) vs 423.00 (ours).
The official C++ was verified deterministic across 5 reruns (only the XML
header's output-path comments differ), so this is a Rust junction-model bug,
not a heap-order/uninitialised-memory artefact. Two scooters are already stopped
on `:C_10_0` (pos 17.00 and 13.90); the likely root cause is in the
minor-link approach-speed / `checkRewindLinkLanes` handling of a blocked
internal lane. `planMoveInternal`, `checkRewindLinkLanes`, `keepClear` and
`getSpaceTillLastStanding` currently match the C++ line-for-line in the
suspected sections, so no faithful fix was found.
